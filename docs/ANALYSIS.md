# Разбор zapret-discord-youtube 1.10.4 и что из этого выросло

Документ описывает устройство сборки [Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube) версии 1.10.4, историю изменений, механизм обновления, слабые места и то, как устроено приложение Zapret Control, собранное в этом репозитории.

## 1. Что это за проект

Это не самостоятельный обход и не VPN. Это **набор конфигураций и bat-скриптов** для `winws.exe` из проекта [bol-van/zapret](https://github.com/bol-van/zapret) (Windows-порт). `winws.exe` перехватывает пакеты через драйвер WinDivert и модифицирует их так, чтобы DPI провайдера не распознал TLS/QUIC-соединение: режет TLS ClientHello на части, подмешивает фейковые пакеты, меняет порядок и т.д.

Лицензия upstream: MIT, copyright bol-van и Flowseal. Бинарники в `bin/` взяты из `zapret-win-bundle` и релизов zapret, сама оболочка (bat + списки) написана Flowseal и контрибьюторами.

Ключевой вывод: **ценность проекта в подобранных стратегиях и списках**, а не в коде. Код оболочки - это cmd-скрипты, которые собирают командную строку для `winws.exe`.

## 3. Как устроена стратегия

Стратегия это один вызов `winws.exe` с глобальными опциями и набором профилей, разделённых `--new`:

```
winws.exe --wf-tcp=80,443,2053,2083,2087,2096,8443,12 --wf-udp=443,19294-19344,50000-50100,12
  --filter-udp=443 --hostlist=list-general.txt ... --dpi-desync=fake --dpi-desync-repeats=11
    --dpi-desync-fake-quic=quic_initial_www_google_com.bin
  --new --filter-udp=19294-19344,50000-50100 --filter-l7=discord,stun --dpi-desync=fake ...
  --new --filter-tcp=2053,2083,2087,2096,8443 --hostlist-domains=discord.media ...
  --new --filter-tcp=443 --hostlist=list-google.txt --ip-id=zero ...
  ...
```

Что важно понимать:

* `--wf-tcp` / `--wf-udp` - какие порты вообще перехватывать (WinDivert-фильтр). В них подставляется GameFilter-порт или заглушка `12`.
* `--filter-tcp/--filter-udp` - порты конкретного профиля.
* `--filter-l7=discord,stun` - распознавание протокола по содержимому.
* `--hostlist`, `--hostlist-domains`, `--ipset` и `*-exclude` - к каким адресам применять профиль.
* `--dpi-desync` - цепочка методов. В сборке встречаются `fake`, `multisplit`, `fakedsplit`, `hostfakesplit`, `multidisorder`, `syndata`.
* `--dpi-desync-split-pos`, `-split-seqovl`, `-split-seqovl-pattern` - где и как резать TLS.
* `--dpi-desync-fooling=ts|md5sig|badseq|datanoack` - способ обмануть проверку TTL/контрольных сумм.
* `--dpi-desync-repeats` - сколько раз повторять фейк.
* `--dpi-desync-cutoff` - после какого пакета перестать вмешиваться.
* `--dpi-desync-fake-tls/http/quic/discord/stun/unknown` - какими байтами подменять.
* `--ip-id=zero` - обнуление IP ID (для Google).

## 4. service.bat: что внутри

12 пунктов меню, но реально это 4 подсистемы.

1. **Служба.** `sc create zapret binPath= "\"...\winws.exe\" аргументы" start= auto`. Аргументы берутся из выбранного bat-файла: скрипт читает файл построчно, ищет строку с `winws.exe`, склеивает продолжения `^` и вручную пересобирает аргументы. Отдельная возня с `!` (экранирование в cmd), с `--sni/--host/--altorder` (аргументы со значением), c кавычками и относительными путями. Это самый хрупкий код проекта: любое изменение формата bat-файла ломает установку службы. Имя установленной стратегии пишется в реестр `HKLM\System\CurrentControlSet\Services\zapret\zapret-discord-youtube`.
2. **Settings.** GameFilter (режимы TCP/UDP/ALL + диапазоны портов, файл `utils/game_filter.enabled`), IPSet (3 режима через содержимое `ipset-all.txt`), автопроверка обновлений (наличие `utils/check_updates.enabled`), замена активных фейков Discord/GameFilter копированием `.bin`.
3. **Updates.** Проверка версии, обновление IPSet, обновление hosts, открытие страницы релиза.
4. **Tools.** Диагностика и запуск PowerShell-тестов.

Диагностика проверяет: BFE, системный прокси, TCP timestamps (и включает их), Adguard, Killer, Intel Connectivity, Check Point, SmartByte, кириллицу в пути, OneDrive, наличие `WinDivert64.sys`, VPN-службы, DoH, записи youtube.com в hosts, остаточную службу WinDivert, конфликтующие обходы (GoodbyeDPI, discordfix_zapret, winws1/winws2), кэш Discord.

## 5. test zapret.ps1: как подбирается стратегия

* Режимы: стандартные тесты (HTTP/1.1, TLS 1.2, TLS 1.3, ping по `targets.txt`) или DPI-тесты (TCP 16-20 КБ по списку с `dpi-checkers`).
* Каждая стратегия запускается через `cmd /c <bat>`, ждётся `winws.exe`, затем цели проверяются параллельно в runspace pool через `curl.exe`.
* Перед DPI-тестами IPSet принудительно переводится в `any`, после - восстанавливается; при закрытии окна крестиком восстановление откладывается до следующего запуска (флаг `ipset_switched.flag`).
* В конце печатается аналитика и «лучший конфиг» (по числу успешных проверок, потом по ping). Результаты пишутся в `utils/test results/`.
* DPI-тест: POST 64 КБ, признак блокировки - отправка прошла, ответа после ~16 КБ нет.

Ограничения: долго (перезапуск процесса на каждую стратегию), только текст в консоли, нет истории и сравнения, нет учёта того, что 16-20 КБ тест ломается при включённом IPSet (поэтому его и выключают).

## 6. Как обновляется upstream

В проекте нет автообновления бинарников. Есть три разных механизма:

1. **Проверка версии.** `LOCAL_VERSION` захардкожен во второй строке `service.bat`. При каждом запуске стратегии вызывается `service.bat check_updates`: если существует `utils/check_updates.enabled`, в фоне запускается `service check_updates soft`, который сравнивает `LOCAL_VERSION` с `https://raw.githubusercontent.com/.../main/.service/version.txt` и при различии **открывает страницу релиза в браузере**. Скачивания нет, распаковки нет, миграции нет.
2. **IPSet.** Пункт меню скачивает `.service/ipset-service.txt` через curl прямо в `lists/ipset-all.txt` (без резервной копии).
3. **Hosts.** Пункт меню скачивает `.service/hosts`, сравнивает первую и последнюю строку с системным hosts и, если не совпало, открывает блокнот и проводник: пользователь копирует вручную.

Обновление самой сборки - вручную: скачать архив, распаковать поверх, сохранив пользовательские файлы. Ради этого в 1.9.7 и появились `*-user.txt`: чтобы при замене файлов не терять свои домены. При этом `game_filter.enabled`, `check_updates.enabled` и заменённые `ACTIVE_*.bin` всё равно можно потерять, а старые стратегии, удалённые из новой версии, остаются лежать в папке.

## 8. Слабые места upstream

По коду и по обсуждениям в issues (494 открытых/закрытых, самые обсуждаемые - «не работает Discord», «сломался YouTube») видно:

1. **Batch как платформа.** Ручной парсинг аргументов для службы, переключение кодовых страниц (`chcp 65001` / `437`), чувствительность к кодировке и CRLF, проблемы с кириллицей и `&` в пути.
2. **22 почти одинаковых bat-файла.** Нет структурного описания стратегии: чтобы поменять один фейк, правится 20 файлов, а в service.bat зашит ещё и парсер этого текста.
3. **Нет GUI.** Меню на 12 пунктов, ввод цифр, `pause` после каждого действия.
4. **Нет настоящего обновления.** Только открытие страницы релиза. IPSet скачивается без резервной копии, hosts - вручную через блокнот.
5. **Ошибки winws не видны.** Запуск через `start /min`, лог нигде не сохраняется, служба пишет в системный журнал, который никто не смотрит.
6. **Служба и ручной запуск конфликтуют.** Если служба работает, обычный bat надо закрывать, иначе два winws дерутся за WinDivert.
7. **Тесты медленные и текстовые.** Нет истории, сравнения по провайдерам, нет применения лучшей стратегии одним кликом.
8. **Нет проверки целостности.** Антивирусы удаляют `WinDivert64.sys`, архивы пересобираются сторонними людьми, а приложение об этом не сообщает.
9. **Нет реакции на смену сети.** При переходе с Wi-Fi на мобильный интернет рабочая стратегия часто перестаёт работать, но пользователь узнаёт об этом по «Discord не грузится».

## 9. Что сделано здесь

### Архитектура

```
src/Zapret.Core      библиотека без UI
  BatStrategyParser  разбор .bat в структуру (аргументы, профили, фильтры)
  WinwsCommandBuilder сборка командной строки обратно (1:1 с bat)
  GameFilter         чтение/запись utils/game_filter.enabled
  IpSetManager       режимы none/any/loaded
  UserLists          пользовательские списки
  WinwsRunner        запуск winws, журнал, контроль процесса
  ServiceManager     установка/удаление службы zapret
  Diagnostics        25 проверок с кнопками исправления
  Prober             HTTP/1.1, TLS 1.2, TLS 1.3, ping
  DpiTester          тест блока 16-20 КБ на сыром сокете
  StrategyTester     перебор стратегий с оценкой
  UpdateService      проверка, скачивание, установка, откат, hosts, ipset
src/Zapret.App       WPF-интерфейс (net9.0-windows, тёмная тема)
src/Zapret.Check     консольные проверки: парсер, round-trip, версии, апдейтер
```

### Принципиальные решения

* **bat-файлы остаются источником правды.** Парсер читает их и восстанавливает командную строку байт в байт (проверяется round-trip тестом), поэтому обновление upstream не требует правок приложения: достаточно перечитать файлы.
* **Структурная модель вместо регулярных выражений.** Профили, фильтры, desync-параметры и фейки доступны в UI, а служба ставится из готового списка аргументов, а не из повторного парсинга текста.
* **Один winws на папку.** Запуск проверяет, не работает ли служба, и не убивает чужие процессы: `KillAllFrom` сравнивает путь исполняемого файла.
* **Обновление как транзакция.** Скачивание, проверка архива, резервная копия, замена, проверка результата, откат при ошибке, восстановление службы и стратегии.
* **Пользовательские данные неприкосновенны.** `list-*-user.txt`, `ipset-exclude-user.txt`, `ipset-all.txt`, `game_filter.enabled` и заменённые `ACTIVE_*.bin` сохраняются (последнее можно отключить).

### Функции приложения

* Список стратегий с human-readable разбором каждого блока: порты, scope, desync, повторы, fooling, cutoff, фейки.
* Запуск/остановка, статус, время работы, журнал winws с сохранением в файл.
* Установка любой стратегии в службу автозапуска и удаление службы.
* GameFilter: режимы и диапазоны портов с валидацией.
* Подбор стратегии: последовательный перебор, HTTP/TLS/ping по выбранным сервисам, DPI-тест 16-20 КБ, оценка, сортировка, запуск лучшей двойным щелчком.
* Диагностика: 25 проверок, включая локализацию sc.exe, остаточный WinDivert, конфликты, hosts, DoH, DNS, версию WinDivert, целостность файлов.
* Списки: редактирование пользовательских файлов, добавление домена, режимы IPSet, обновление списка и hosts с маркерами `zapret-control` (без блокнота).
* Обновления: проверка последнего релиза, история изменений, скачивание и установка, резервные копии, пропуск версии, авто-проверка при старте.

### Как работает встроенный апдейтер

1. `GET /repos/Flowseal/zapret-discord-youtube/releases/latest`, берётся zip-ассет.
2. Установленная версия читается из `LOCAL_VERSION` в `service.bat`.
3. Сравнение версий с учётом суффиксов (`1.9.9d < 1.10.4`).
4. Скачивание с прогрессом, SHA256 в интерфейсе.
5. Распаковка во временную папку, поиск корня, проверка `bin/winws.exe`, `WinDivert64.sys`, `lists`, `utils`, `general*.bat`.
6. Остановка winws этой папки и удаление службы (только если её ImagePath указывает на эту папку).
7. Полная резервная копия в `../zapret-backups/<имя>-<дата>`, хранятся 3 последние.
8. Замена `bin`, `utils` и `*.bat`. `lists/list-general.txt`, `list-google.txt`, `list-exclude.txt`, `ipset-exclude.txt`, `ipset-all.txt.backup` и `utils/targets.txt` не перезаписываются, а **сливаются по трём версиям**: база - файл из установленной версии (скачивается по тегу), наши - локальный файл, новые - из архива. Правки пользователя сохраняются, новые строки добавляются, удалённые upstream строки убираются только если пользователь их не менял. Без сети используется безопасное объединение: локальный файл плюс только новые строки. Для загруженного IPSet активный список сливается тем же способом, поэтому ручные подсети не теряются.
9. Удаление стратегий, которых больше нет в релизе.
10. Проверка, что `winws.exe` на месте; при ошибке - откат из копии.
11. Перечитывание стратегий, восстановление службы и запуск той же стратегии, если она работала.

Режим обработки списков переключается в интерфейсе: объединять (по умолчанию), заменить новыми, оставить мои. Отключённая пользователем автопроверка обновлений (`utils/check_updates.enabled` удалён) сохраняется, а не включается обратно. При включённой галочке «Устанавливать обновления автоматически» весь сценарий выполняется при старте приложения без вопросов, результат показывается в трее. Приложение запускается с правами администратора (манифест `requireAdministrator` плюс резервный перезапуск через `runas`).

Ограничения текущей версии: обновляется только upstream-сборка (свой feed появится в `AppInfo.SelfRepo`), нет подписи загружаемых архивов (проверяется только структура и хэш для информации), hosts применяется целиком блоком и требует прав администратора.
